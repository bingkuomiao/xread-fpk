# xread-fpk 打包流程验证报告

生成时间：2026-11-18
本地工作目录：`xread-fpk-next`（即推送到 `bingkuomiao/xread-fpk` 的工程主体）
目标：固化「从 xread + xread-kindle 拉取最新产物 → 统一打包 FPK」流程，作为新 `bingkuomiao/xread-fpk` 库（原库已归档为 `xread-fpk2`）的工程主体；应用版本 1.0.48.69，内置 Kindle 静态前端支持。

## 一、工程定位

打包工程**只负责组装与打包**，不再是源码基线。源码基线两个独立仓库：

| 源码基线 | 提供什么 | 本地默认路径 |
|---|---|---|
| `bingkuomiao/xread` | Rust 后端（二进制）+ Vue3 前端（源码） | `../xread` |
| `bingkuomiao/xread-kindle` | Kindle/手机/PC 静态前端（源码即产物） | `../kabi-reader` |

三类产物来源：

- **Vue3 前端**：`npm run build` 现编译（版本号由 `package.json` 注入）
- **Kindle 前端**：源码直接复制
- **后端二进制**：本地固定基线，或从 xread 的 `backend-latest` Release 拉最新产物

## 二、关键文件

| 文件 | 作用 |
|---|---|
| `build.sh` | 主脚本：拉产物→编译前端→注入配置→组装→校验→fnpack 打包 |
| `tools/fetch-backend.sh` | 从 `backend-latest` Release 拉最新后端二进制，SHA256 + 静态 ELF 校验后才替换基线 |
| `tools/patch_dist.py` | 构建产物层注入 `window.__XREAD_CONFIG__`（不改源码，幂等） |
| `tools/fnpack` | fnOS 打包器 |
| `manifest` / `cmd/` / `config/` / `wizard/` / `ICON*.PNG` | fnOS 打包壳 |
| `backend/` | 后端二进制落地目录（基线 / fetch 更新） |
| `README.md` | 操作手册 |

## 三、本次新增/升级

1. **`--fetch-backend`**：`build.sh` 新增参数，打包前从 xread 的 `backend-latest` Release 拉最新后端二进制（配合 `--pull` 实现前后端都取最新）。
2. **`tools/fetch-backend.sh`**（新增）：
   - 用 GitHub API 读取 Release 元数据，解析三个资产下载地址
   - 匿名下载（公开 Release）+ **curl 重试 5 次**（应对网络抖动）
   - 校验 `SHA256SUMS` + `file` 检查 64 位 ELF/静态链接
   - 全部通过才覆盖本地 `backend/`，失败不动基线
   - 支持 `GITHUB_TOKEN`（避免限流/私有仓）、`XREAD_REPO`、`RELEASE_TAG`、`BACKEND_DIR` 环境变量
3. **BUILD_INFO** 区分后端来源：`local backend/ baseline` 或 `xread@backend-latest Release (SHA256 verified)`。
4. README 补全三件套用法、后端自动编译工作流说明、首次运行提示。

### 4.3 后端拉取（backend-latest Release）
- xread 的 `build-backend.yml` 已首次运行并创建 `backend-latest` Release（API 查询 HTTP 200，元数据可正常读取并解析出三个资产 URL）。
- **真实外网大文件下载受沙箱网络限制**：下载 23MB 二进制时多次 `Connection reset by peer` / 超时（曾到 11MB/23MB 断开），脚本的 curl 重试 5 次仍未能在此环境完成。这是沙箱网络问题，非脚本逻辑问题。
- 改用**本地模拟 GitHub Release 服务器**做端到端验证（脚本新增 `GITHUB_API` 环境变量支持指向自托管/模拟地址）：
  - 元数据解析 → 下载 amd64/arm64 → SHA256 校验（OK）→ 静态 ELF 校验 → 落地，**全流程通过**；落地文件 SHA 与源一致。
- 失败时不动基线：真实下载失败期间本地基线 SHA 始终未变（与备份一致）；模拟篡改资产时校验失败并拒绝替换（见 4.5）。

### 4.4 幂等性
- `patch_dist.py` 重复运行：首次注入 2 处、重复运行 0 处，幂等正常

### 4.5 安全校验
- 模拟资产被篡改（制造 SHA 不匹配）：脚本 `sha256sum -c` 检测到 FAILED，退出码 1，**拒绝替换本地基线**，目标目录原有文件完好。
- 静态 ELF 校验：非 64 位 ELF 或非静态链接的资产会被拒绝。
